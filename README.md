# Attendance Record

A Laravel-based attendance registration system with Docker support. Features public event registration with digital signature capture, a Filament admin panel, QR code generation, and XLSX/PDF reporting.

## Documentación

- [Manual de usuario](docs/MANUAL_DE_USUARIO.md)
- [Documentación técnica](docs/DOCUMENTACION_TECNICA.md)
- [Índice de documentación](docs/README.md)

## Tech Stack

- **Backend:** Laravel 13 (PHP 8.3+; Docker uses PHP 8.4)
- **Frontend:** Tailwind CSS v4, Vite, Signature Pad
- **Admin Panel:** Filament v5
- **Database:** MySQL 8.4
- **PDF/Reports:** DOMPDF, FPDF, PhpSpreadsheet
- **QR Codes:** Bacon QR Code
- **Containerization:** Docker & Docker Compose

## Services

## Quick Start

### Prerequisites

- Docker Engine & Docker Compose
- Make (optional, for convenience commands)

### Setup

1. Copy Laravel environment variables and configure the Docker database connection:

   ```bash
   cp src/.env.example src/.env
   ```

   In `src/.env`, use at least:

   ```dotenv
   APP_URL=http://localhost:8080
   DB_CONNECTION=mysql
   DB_HOST=db
   DB_PORT=3306
   DB_DATABASE=laravel
   DB_USERNAME=laravel
   DB_PASSWORD=laravel
   ```

2. Start the services and prepare the application:

   ```bash
   docker compose up -d --build
   docker compose run --rm app php artisan key:generate
   docker compose run --rm app php artisan migrate
   docker compose run --rm app php artisan db:seed
   docker compose run --rm app php artisan storage:link
   ```

   The `vite` service is commented out in the local Compose file. Build assets with Node/pnpm from `src/` when `public/build` is not available:

   ```bash
   cd src
   corepack enable
   pnpm install --frozen-lockfile
   pnpm run build
   ```

3. The application is available at:

   - **App:** http://localhost:8080
   - **Vite HMR:** http://localhost:5173 (only when started manually)
   - **phpMyAdmin:** http://localhost:8081

## Gestión de usuarios

El acceso al panel de administración se controla mediante el campo `is_admin` del usuario:

- `is_admin = true`: puede iniciar sesión en `/admin`.
- `is_admin = false`: no puede acceder al panel de administración.

Actualmente no existe un formulario público de registro ni un recurso de usuarios dentro de Filament. Las altas y la recuperación del acceso administrativo se realizan mediante comandos Artisan dentro del contenedor `app`.

### Crear un usuario sin acceso al administrador

Ejecuta el seeder interactivo desde la raíz del proyecto:

```bash
docker compose run --rm app php artisan db:seed --class=UserSeeder
```

El comando solicita el nombre, correo electrónico, contraseña y si el usuario será administrador. Para crear un usuario sin acceso al panel, responde `No` a la pregunta `¿Es administrador?`.

Consideraciones:

- La contraseña debe tener al menos 8 caracteres.
- El correo electrónico no puede estar registrado previamente.
- `UserSeeder` no se ejecuta con `php artisan db:seed`; debe indicarse explícitamente mediante `--class`.
- Un usuario no administrador se almacena correctamente, pero actualmente no existe una pantalla de inicio de sesión ni un área privada específica para ese tipo de usuario.

### Crear o activar `admin@example.com`

Si el usuario no existe, créalo con el seeder administrativo:

```bash
docker compose run --rm app php artisan db:seed --class=AdminUserSeeder
```

Este comando crea `admin@example.com` con la contraseña inicial `admin123`. Si el registro ya existe, el seeder solo informa que ya existe y no modifica su estado.

Si el usuario existe pero no tiene acceso al panel, activa el permiso administrativo:

```bash
docker compose run --rm app php artisan tinker --execute='App\Models\User::where("email", "admin@example.com")->update(["is_admin" => true]);'
```

Si también es necesario restablecer la contraseña, utiliza una instancia del modelo para que Laravel aplique el hash configurado:

```bash
docker compose run --rm app php artisan tinker --execute='App\Models\User::where("email", "admin@example.com")->firstOrFail()->forceFill(["is_admin" => true, "password" => "ReemplazarConUnaClaveSegura"])->save();'
```

Después de activar la cuenta, accede a `http://localhost:8080/admin`. Cambia inmediatamente la contraseña inicial en cualquier entorno que no sea local y no uses `admin123` en producción.

## Key Features

- **Public Event Registration:** Attendees register via a public form (`/evento/{slug}`) with separate names and surnames, normalized numeric identification, catalog-based headquarters and positions, and digital signature capture.
- **Admin Dashboard:** Filament-powered admin panel for managing events, attendance records, positions, headquarters, and reasons.
- **QR Code Generation:** For event check-in or quick access links.
- **Attendance Reports:** XLSX and PDF reports can be filtered by event and multiple headquarters (`headquarter_ids[]`).
- **PDF Reports:** Generated with FPDF; DOMPDF remains available as a declared dependency.
- **Spanish UI:** All interface labels and validation messages in Spanish.
- **Soft Disabling:** Positions, headquarters, and reasons can be soft-disabled via `is_active` boolean.

## Common Commands

### Docker

```bash
# Start all services
docker compose up -d

# Stop all services
docker compose down

# View logs
docker compose logs -f [service]

# Run artisan commands
docker compose run --rm app php artisan [command]

# Run composer
docker compose run --rm app composer [command]

# Run tests
docker compose run --rm app php artisan test

# Build assets (with Node/pnpm available from src/)
cd src && pnpm install --frozen-lockfile && pnpm run build
```

### Inside the `app` Container

```bash
docker compose exec app bash

# Then run Artisan or Composer commands directly
php artisan migrate:fresh --seed
composer install
```

## Customization

### Admin Panel Theme

The Filament admin panel theme is customized via:

- `src/app/Providers/Filament/AdminPanelProvider.php` — brand name, colors, fonts, theme registration.
- `src/resources/css/filament/admin/theme.css` — custom CSS overrides for Filament components.

### Public Pages Theme

Public pages use custom Tailwind colors defined in `src/resources/css/app.css` (`navy-*`, `gold-*`, `warm-*`). These are independent from the admin theme; redefine them in both files if needed.

```bash
docker compose run --rm app php artisan test
```

## Despliegue en Coolify

En Coolify se debe utilizar `docker-compose.coolify.yml` como archivo de Compose y configurar las variables sensibles en el entorno del recurso:

- `APP_KEY`
- `APP_URL`
- `DB_DATABASE`
- `DB_USERNAME`
- `DB_PASSWORD`
- `DB_ROOT_PASSWORD`

El contenedor de la aplicación ejecuta `php artisan migrate --force` antes de iniciar PHP-FPM. `RUN_MIGRATIONS` queda habilitada por defecto y solo debe establecerse en `false` si las migraciones se administran mediante un comando de despliegue independiente.

El almacenamiento persistente de archivos adjuntos corresponde al volumen `public_storage`; la base de datos utiliza `db_data`. Ambos volúmenes deben conservarse entre despliegues.
